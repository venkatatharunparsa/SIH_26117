Sovereign Workbench

Proposed Solution (Describe your Idea/Solution/Prototype)
• Sovereign Workbench — air-gapped agentic workbench on the org GPU (not a chatbot)
• Scan → on-device OCR → task-routed open-weight models → HITL fact-sheet → Word + Excel
• Coding task run and verified in Docker --network=none (GPU server stays outside the jail)

How it addresses the problem
• Confidential notes/P&IDs cannot go to Claude/Codex; PS requires own GPU + zero external calls
• Auto-select ≥2 task types (extract vs code) via Model Cards + OpenAI-compatible /v1 gateway
• Real deliverable (python-docx), citations or NOT FOUND, draft watermark, visible WAN-off log

Innovation and uniqueness of the solution
• vs Open WebUI/Ollama/PrivateGPT: task gateway, controlled templates, sandbox calc, HITL, egress proof
• vs ChatGPT/Copilot: nothing leaves premises; 7B-class sequential on RTX 4060 8 GB (PS allows smaller models)
• Not plant DCS control. Not a new LLM. Integration for industrial documents + proof of sovereignty

FEASIBILITY AND VIABILITY

Analysis of the feasibility of the idea
• PS allows mid-range GPU / smaller models if 120B absent — 8 GB is that case
• 36h REAL: OCR, two model ids, HITL JSON, Word, Excel CR, sandbox tests, WAN-off log
• MOCKED (same schema): EAM/historian JSON · NOT claimed: SAP, 14B, PPT, two models in VRAM

Potential challenges and risks
• Small-model tool-calling / OCR on bad scans · Docker Desktop blocked at venue · fake-looking routing

Strategies for overcoming these challenges
• Sequential two GGUF ids (not two prompt labels) · OCR confidence + NOT FOUND · calc only in sandbox
• Docker primary; WSL jail fallback (disclose if weaker) · WAN unplug + host/packet log · draft forever
